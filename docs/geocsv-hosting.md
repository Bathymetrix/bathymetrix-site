# GeoCSV hosting

The read-only Cloudflare Worker serves GeoCSV snapshots from private R2.
`mermaid-publisher` owns snapshot creation, exhaustive scientific validation,
gating, upload, latest activation and archive recording. Follow its
[contract](../../mermaid-publisher/docs/geocsv/contract.md) and
[workflow](../../mermaid-publisher/docs/geocsv/workflow.md).
The [payload schema](../../mermaid-geocsv/docs/format-spec.md) and scientific
APIs belong to the consumer. Hosting never interprets or rewrites scientific data.

## Routes and bytes

The Worker accepts only GET/HEAD. It serves isolated collection-relative
`latest.json`, `latest/` and `latest/<instrument>.geocsv` temporary 302 redirects, and
`releases/<component>/{manifest.json,validation.json,<instrument>.geocsv}`.
Deployed bundle support adds the exact `MERMAID.geocsv.tar.gz` filename, served
as `application/gzip` with an attachment filename and no HTTP content encoding.
Its stored gzip bytes retain the immutable/no-transform policy.
Latest and redirect responses bypass caches. Successful immutable objects use
`public, max-age=31536000, immutable, no-transform`; misses and errors are not
cached. `Cache-Control: no-cache` or `no-store` forces a storage read for
verification. HEAD returns object metadata without a body. Payloads are stored
uncompressed, streamed without transformation and served with exact byte counts.
The browser URL `https://bathymetrix.com/geocsv/testing/latest/` redirects to
the currently selected release directory. The redirect follows the isolated
latest pointer on every request; an absent pointer returns 404.
Deployed and verified on 2026-11-04: GET/HEAD returned an uncached 302 to the
selected testing directory, and following the redirect returned 200 with
instrument files and the bundle. Production `latest/` remained 404.

Only the two creation-timestamp time-separator colons become hyphens in paths.
JSON release identities retain the original spelling and fractional digits.
Literal-colon and percent-encoded release components are rejected before cache
lookup. There are no upload/admin routes or schema-dependent rewrites.

### Browser archive listings

Listing routes implemented in this checkout are `/geocsv/testing/`, `/geocsv/testing/index.html`,
`/geocsv/testing/releases/` and the separate production `/geocsv/releases/`.
They use paginated read-only R2 listing and manifests; directories without a
manifest are omitted. Identity/path/collection flags must agree or return an
uncached 503. Deployed pages use a plain clickable directory tree,
with exact release components and a latest marker. Each
`releases/<component>/` URL opens its own file tree, independent of latest.
Instrument links come from the manifest; validation and bundle links appear
only when the corresponding objects exist. Missing release manifests return
404. Listings do not parse schemas or establish acceptance. They use no browser
JavaScript and respond `no-store`. The static preview cannot generate these
Worker-owned pages.

Directory-tree, per-release page, bundle and auxiliary-report routes were
deployed on 2026-11-03. Existing hosted snapshots have no automatic bundle or
report backfill. Further deployments and uploads require explicit authorization. The publisher
builds and records bundles; this Worker serves existing objects only.

## Deployment and access constraints

Use `workers/geocsv/wrangler.example.jsonc` as a portable template. Actual
configuration, approved bucket/account settings, SDK credentials and DNS records
remain in private locations outside checkouts. Resolve an external configuration's
entry point relative to that file or use an absolute path. Keep public bucket
URLs disabled and the Worker binding read-only. The SDK provider owns credentials.
Do not print them or store them in repository files, including ignored files.

Cloudflare is authoritative, DNSSEC is enabled, website TLS uses Full (strict),
and GitHub Pages remains origin. Only the approved website hostnames are proxied;
mail/service records retain their intended routing. The GeoCSV route requires
proxied DNS. Python GET/HEAD clients require the scoped Browser Integrity Check
exception for the collection; do not disable unrelated security controls.
No zone-wide cache rule should override exact-byte, no-store or uncached-error
behavior. Actual DNS inventories and account settings remain private.

Before an authorized deployment, run Worker tests and review the external
configuration, route and binding. After deployment verify static pass-through,
GET/HEAD, testing flags, pointer isolation, immutable exact bytes and uncached
misses using ordinary Python clients. Verify schema compatibility separately
through public fetch/read APIs. A deployment does not authorize data upload.

### Deployment commands

`MERMAID_PUBLISHER_GEOCSV_CONFIG` names the private configuration directory.
The site deployment commands read `wrangler.jsonc` from that directory; the
publisher separately reads `r2.json` and `instruments.csv`. The Worker name,
route, binding and approved storage destination must be checked before deploying.
The supplied configuration remains outside this checkout. Its `main` can point
to the Worker source; the commands explicitly select this checkout's entry point.

Use a supported Node.js LTS runtime (Node >= 22) and the pinned Wrangler version:

```bash
cd workers/geocsv
npm ci
npm test
npm run deploy:plan
```

The plan compiles and checks the Worker without uploading it. After explicit
deployment authorization, run `npm run deploy`. It reruns the tests and uses
Wrangler's strict conflict check. Both commands require the directory variable
and disable automatic project reconfiguration. They do not publish snapshots
or activate a data pointer. Keep configuration-bearing deployment logs private
and outside repository files; do not paste their values into public evidence.

### Recovery

Inspect live state before retries or activation recovery. A Worker fault can be
isolated by removing its route or reverting website proxying while preserving
GitHub Pages; either is an explicitly authorized infrastructure operation.
DNS-provider rollback requires compatible DNSSEC/DS state and verification of
website, redirects and mail after resolver caches expire. Do not restore an
incompatible DS record. Data rollback changes only a separately authorized latest
pointer after verification; immutable snapshots are never rewritten.

## PPHC header and testing schema

The writer emits dataset-first GeoCSV 2.0 with `schema: MERMAID GeoCSV
v1.0.0-rc1`, padded comment keywords, unquoted comma/LF declarations and
producer/publisher/hoster/consumer project descriptions. `references` is reserved
for the describing paper and omitted until its DOI exists. Final schema 1.0.0
is reserved for paper publication. Testing accepts the 1.0.0 version family,
retains the exact revision and applies all scientific requirements.

This header requires consumer >= 0.29.0 and publisher >= 0.8.0. Testing latest
serves the full-corpus rc1 snapshot `2026-11-05T23:41:47.235000Z`. Older retained
snapshots keep their original headers and may be incompatible with this reader.
Canonical sources remain read-only. Testing publication does not authorize
production activation or retirement.
